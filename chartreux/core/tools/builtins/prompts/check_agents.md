List the bounded background-agent inventory and each entry's current availability and run status. This is nonblocking and takes no arguments. Availability is `running`, `finalizing`, `idle`, `evicted`, or `closed`. A `running` agent has an active run. A `finalizing` agent has completed its run but is still committing its terminal result and cannot yet be reused. An `idle` agent is retained and resident: the top-level `reuse_guidance` explains how to continue it with `task(agent_id=..., background=true, task=...)`; omit `agent_type` to retain its profile. A `closed` agent completed without retention (normal completion, including failed or cancelled runs) and cannot be reused. An `evicted` agent was retained but its runtime was removed by the idle TTL or idle cap and cannot be reused. Closed and evicted entries are terminal metadata in a bounded window: they disappear when the metadata expires, but their completed results remain available through `get_agent_result` until result expiry. Each entry's `agent_id` is an instance handle, while `profile` names its agent type and `name` is its display-only `{profile}-{model}-{number}` label; `agent_id` is the only handle. The `agent-N` syntax (digits after `agent-`) is reserved for instance handles, not profile names. Each entry includes its `profile`, `initial_task_summary`, `current_task_summary`, `effective_model`, `effective_thinking`, `idle_seconds`, and `ttl_remaining_seconds`; the TTL is advisory only and does not guarantee availability. `effective_thinking` is the semantic call-level/lower-layer choice, not provider wire-level encoding.
