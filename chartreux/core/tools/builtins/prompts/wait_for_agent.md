Prefer ending your turn and fetching with `get_agent_result` on the completion notification, even when your next substantive action depends on the result. Use this blocking tool only if the result is a hard dependency of your next action, no independent work can proceed, and that action must occur in this turn rather than after notification. If uncertain, end your turn. Do not invent independent work or dispatch unnecessary tasks to fill the wait; if there is nothing real to do, end your turn. Blocking keeps this turn open; queued user input is delivered between turns.

Supply `agent_id`, optionally `run_id` for a specific invocation, optionally a positive `timeout` in seconds (default 1500; pass null to wait indefinitely), and `mode` — `"digest"` (default) or `"full"` for the delivered result body. The result is a typed disposition, not a failure on timeout: `completed` carries the finished run's result, and `still_running` — returned when the timeout expires first — carries `agent_id`, `run_id`, `elapsed_seconds`, `run_status`, `turns_used`, and `guidance`. A timeout stops only this wait; it never cancels the background run. The delivery marking is shared with `get_agent_result`: a run already delivered in the same mode with no compaction boundary since is mechanically refused unless `force=true`. On `still_running`, end your turn or continue independent work; never re-invoke the wait in the same turn. Prefer the completion notification and `get_agent_result`. In a later turn, re-wait only if the same three conditions still hold. Use `check_agents` to inspect progress while the run is active. A `closed` or `evicted` agent cannot accept new work, but waiting on one returns its preserved result while it remains retained. A result-expired error means no result remains, and an unknown-agent or unknown-run error means the handle is invalid; use `check_agents` to inspect handles.
