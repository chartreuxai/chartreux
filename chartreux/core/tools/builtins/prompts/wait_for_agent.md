Wait for a background subagent run to complete. Supply `agent_id`, optionally `run_id` for a specific invocation, optionally a positive `timeout` in seconds (default 1500; pass null to wait indefinitely), and `mode` — `"digest"` (default) or `"full"` for the delivered result body. The result is a typed disposition, not a failure on timeout: `completed` carries the finished run's result, and `still_running` — returned when the timeout expires first — carries `agent_id`, `run_id`, `elapsed_seconds`, `run_status`, `turns_used`, and `guidance`. A timeout stops only this wait; it never cancels the background run. The `still_running` guidance instructs you to end your turn or continue other work now (queued user input is only delivered between turns) and to re-invoke `wait_for_agent` in a later turn to keep waiting; never re-invoke it in the same turn. The primary completion signal is the completion notification, which arrives when the run finishes: fetch the result then with `get_agent_result` (`mode="digest"` by default, `mode="full"` for the full body) instead of blocking, or keep waiting with this tool (same modes; the delivery marking is shared with `get_agent_result`). Wait only when the result is a hard dependency of your next action and no other work can proceed; otherwise end your turn and collect on the completion notification. Use `check_agents` to inspect progress while the run is active. A `closed` or `evicted` agent cannot accept new work, but waiting on one returns its preserved result while it remains retained. A result-expired error means no result remains, and an unknown-agent or unknown-run error means the handle is invalid; use `check_agents` to inspect handles.
