Explicitly resume a background agent whose run failed and was suspended for recovery. The resume continues the SAME agent identity — conversation, tool state, steering, and cumulative budgets are preserved — under a NEW run_id. Supply `agent_id` and the suspended failed run's `expected_run_id` (from `check_agents`: the `latest_run_id` of a `suspended` agent); `idempotency_key` optionally single-flights retries and omitted defaults to `<agent_id>:<expected_run_id>`. Only the owning parent orchestrator may resume its background agents.

The result is a typed admission disposition: `scheduled` (exactly one successor admitted), `already_scheduled` (a concurrent same-key call deduplicated onto the in-flight admission), `already_resumed` (the pinned failed run already has an admitted successor), `reconcile_required` (tool outcomes are unresolved — verify them and call `reconcile_result` first), `expired` (the recovery window lapsed), `not_resumable` (the agent is not suspended, is prohibited, or the same-agent resume budget is exhausted), or `forbidden` (authority failure). The failed run's result and every wait pinned to it stay immutable; only the failed backend is retired. The successor carries the preserved conversation plus one resume marker and an injected continuation — the injected continuation is NOT a user-initiated retry.

`override_cooldown` optionally forces the un-stick attempt past the committed model's cooldown: it mints an endpoint-bound permit from the root recovery ledger and binds it to the successor's first model call. The ledger still denies the mint when the endpoint's episode is exhausted (two forced starts per episode), spacing-bound (30s between starts), or has an attempt in flight, and a denied mint consumes NOTHING — the resume itself proceeds normally under its plain admission. An accepted override bypasses only the cooldown predicates; a forced attempt is never automatically replayed, and automatic paths never acquire permits.

Every resumed run is also bounded by the first-semantic-progress deadline: its first model call must observe a semantic delta (content, reasoning, or tool-call) within `[recovery.subagents].resume_progress_deadline_seconds` (default 180s) or the in-flight call is killed and the run fails with the measured `resume_progress_deadline` timeout. Heartbeat and usage-only chunks do not count as progress; ordinary (non-resumed) runs are structurally unaffected.

Resume is always explicit: nothing is ever scheduled automatically. Replacement (`task(agent_id=..., replace_run=True)`) and `release_agent` remain available at any point, including while the agent is suspended.
