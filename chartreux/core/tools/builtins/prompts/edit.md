Exact string replacement in a file. You must `read_file` first. When editing text from `read_file` output, never include any part of the line-number prefix in `old_string` or `new_string`. If `old_string` is not found or matches multiple locations, provide more context to make it unique, or use `replace_all`. If an edit fails, re-read the file before retrying. A successful result reports the applied change and the post-edit file state: `applied_diff` shows each replaced site as whole lines (old, then new) under its current line number, `context` is a numbered window of the file's current content around the first site with current line numbers, `replaced_count` is how many sites were replaced, and `revision` identifies the post-edit file state — compare it with a `read_file` `revision` to detect a concurrent change. Client-mediated writes (remote sessions) report no `revision`.
