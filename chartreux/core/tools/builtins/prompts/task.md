Launch a subagent for bounded delegated work of any size. Use `task` to delegate when a specialist is useful; do not treat delegation as limited to exceptional work. Provide a self-contained description and an optional `task_summary`: a concise action plus subsystem or feature (up to 240 characters) used to identify retained agents in `check_agents`. By default it runs in the background and returns a successful launch acknowledgment with `status: "launched"`, non-empty guidance, and `agent_id` and `run_id` handles immediately — it is not the subagent's terminal result, so you can continue working while the subagent runs. The acknowledgment also carries the instance's display-only `name` (`{identity}-{model}-{number}`); `agent_id` remains the only handle.

$dispatch_disclosure

At spawn, the dispatcher hands you your working-set files — the paths this session tree has already observed — with their last-seen content revisions and current symbol outlines, as an injected `<file_state_handoff>` block ahead of this brief. Treat it as metadata: re-read a file for its content. As you read or edit files, one `<file_state>` block is appended per working-set revision change, including revisions published by other workers; these blocks are immutable history, never rewritten.

Select the launch with the canonical top-level fields, all optional: `model`, `identity`, `purpose`, and `seat`. `model` takes one model expression: a canonical model name, an `@role` preset, or the `@<model>[:<identity>]` shorthand — a preset or canonical model name, then optionally an identity component: `:researcher` for a bare built-in identity, `:user:foo` for a `user:`-qualified custom id. `identity` selects who performs the work: a bare built-in (`coder`, `researcher`, `reviewer`, `advisor`, `orchestrator`), a `builtin:`- or `user:`-qualified id, or a bare custom prompt id; the identity's prompt body is the child's contract. `purpose` selects a configured launch route (e.g. `research`) and `seat` picks one target of a multi-seat purpose — never supply `seat` without `purpose`. Missing components are never guessed and conflicts are rejected: the default child identity is `coder` with the bounded-child execution context, the default model is the session model, children never inherit the parent's workflow or strategy, and supplying both `model` and `config.model`, or a shorthand identity component together with the structured `identity` field, is a validation error — no precedence guess. Handles of the form `agent-N` (digits after `agent-`) are reserved for agent instances and rejected as launch targets before dispatch; an unknown retained handle reports `Unknown agent_id instance handle`. The launch acknowledgment's guidance is policy-aware: a retained instance includes guidance to continue it with `task(agent_id=..., background=true, task=...)` once it is idle, omitting the launch fields to keep its committed identity; an unretained instance reports that it closes on completion with the result retrievable. The harness may restrict launchable identities: the task denylist keys on the resolved identity, and a denied launch reports `Task denied for launch identity`.

Launch in the background even when the result is a dependency: background is the default, so launch, then collect the result with `wait_for_agent`. Set `background: false` only when blocking is truly required — the subagent then blocks until completion and returns its final message. Background agents stay inspectable in the `/agents` browser and amendable mid-flight; a foreground launch is not.

Retention is opt-in. By default a background agent closes when its run completes: the result stays retrievable with `get_agent_result` or `wait_for_agent`, and the handle lingers as `closed` terminal metadata until that metadata expires. Pass `retain: true` to keep the instance resident for reuse, subject to the `[subagents]` idle TTL and cap limits. Precedence for a new launch: the `retain` argument, then the `[subagents].retain_agents` default. Reuse with `agent_id` inherits the instance's committed policy; pass `retain: false` for a final continuation that closes afterward. `retain` is rejected for foreground launches.

Use `config` for per-launch configuration: `instructions` (an additive instruction overlay on the identity's prompt body), `thinking`, `enabled_tools`, `disabled_tools`, and `tools` (per-tool `permission`/`allowlist`). `config.model` is the nested model location; supply the model at exactly one level. These typed fields are validated; they cannot expand the parent agent's effective tool authority. `config` is call-level state, not a `[task.config]` setting: it is not written to user or project configuration, but the child commits its resolved base model and concrete provider deployment in session metadata; resume revalidates that identity rather than re-resolving a role.

Two optional fields carry the launch's completion mandates: `completion_check` lists the completion-check templates the task's contract mandates (`pytest`, `ruff_check`, `pyright`, `git_head`, `git_status`, `git_diff_stat`), and `required_artifacts` lists the artifact kinds the worker must deliver (`commit`, `touched_path`, `check_pass`, `envelope`). Both default to unset, which disables only their own mandates (fail-open); the frozen contract is rendered into the child's prompt at admission.

A child completion may fail over between providers for its committed base model before producing semantic output. Inspect `metadata.switch_notices` for each switch's base model, old and new provider, and reason, and `providers_used` for providers involved; failover never changes the child's committed base model.

$dispatch_routing

To supersede busy work, set `replace_run: true` with `agent_id` and `background: true`. Only the owning parent may replace a run. Busy replacement forbids `config` and identity changes; idle reuse still supports launch reconfiguration. The tool stops the old run, joins its cleanup and result publication, then launches in the same conversation, automatically prepending: "This task supersedes the interrupted task." Its existing capacity slot is held through the handoff, so replacement works at capacity. The acknowledgment has `launch_outcome: "launched"` and `metadata.replaced_run_id` / `metadata.replacement_run_id`. Refusals have `launch_outcome: "already_stopping"`, `"already_finishing"`, or `"rejected_reservation"`, not a successful launch status. Retrieve the old run's partial result by its ID; cancellation does not undo side effects. If replacement admission fails after stopping, the old run remains terminal, not resumed. On an idle agent, `replace_run: true` is ordinary reuse with no stop or supersession frame.

For a cross-model replacement after a failure, omit `agent_id` (the replacement gets a NEW handle) and claim the lineage: set the top-level `model` field to the replacement model (the nested `config.model` is the legacy location), plus `config.work_package_id` (the package identity), `config.predecessor_agent_id` (the failed agent), and `config.package_tier` (`mechanical` or `substantive`). Launch admission validates the claim at failure time — endpoint independence from the ATTEMPTED failed endpoint (never the same endpoint, never a mechanical-tier model for a substantive package), the reconciliation barrier (`reconcile_result` first when the failed agent is suspended with unknown tool outcomes), and the per-package replacement budget — and rejects it with a typed reason otherwise. The acknowledgment carries the validated decision and its milestone notice with the honest cost implication; `check_agents` shows the lineage pair on the new agent's summary. Budgets and recurrence counters span replacements and are never reset.

When a selected endpoint sits in a measured cooldown and the work must go out anyway, the explicit boolean `override_cooldown: true` requests a forced un-stick attempt. The flag only REQUESTS the override: root launch admission mints the endpoint-bound permit from the root recovery ledger solely for this explicit request, and the ledger still denies the mint when the endpoint's episode is exhausted (two forced starts per episode), spacing-bound (30s between starts), or has an attempt in flight. A denied mint fails the launch before any budget is consumed and consumes nothing. An accepted override bypasses only the cooldown predicates — allowlists, compaction, thinking, and history checks still apply — and the launch acknowledgment carries the bounded un-stick diagnostics: the forced deployment, the exclusions bypassed, the allowance remaining in the episode, and the next permitted start. The permit is consumed once at the first model call's transport start; a failed forced attempt is never automatically replayed — recovery follows its ordinary cooldown ladder, and any further forced attempt needs a new explicit request. Automatic paths never request the override or acquire permits.

Use `cancel_agent(agent_id, run_id)` to stop background work without replacing it. Acceptance means stop requested, not terminal cancellation. Use `check_agents` to list the bounded agent inventory, `get_agent_result(agent_id, run_id)` to retrieve a completed result without waiting, `wait_for_agent(agent_id, run_id, timeout)` to wait for a run — it returns `completed` with the result, or `still_running` when the timeout expires first, a normal outcome whose guidance tells you to end your turn and re-invoke the wait in a later turn — and `release_agent(agent_id)` to release an agent when its engagement concludes. Releasing an agent discards its retained results and identity—retrieve results before releasing. Background agents cannot be launched from subagents.

A purpose route binds the launch defaults for one purpose: its targets name a model, an identity, a tier, and optionally a seat. Explicit `model` and `identity` fields override the route's corresponding fields; the effective tier is the route target's. An explicit `config.thinking` overrides the resolved thinking level for this launch. If a model or credential is unavailable, repair the preset or credential; no other canonical model is substituted. To run independent agents in parallel, make separate background `task` calls with explicit models or identities, and collect each result by its handle. The retired `fan_out: true` flag returns: “Roles are single presets. Launch separate tasks with explicit presets/models for multiple agents.”
